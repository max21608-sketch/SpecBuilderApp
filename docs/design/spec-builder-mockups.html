The rules the rest of the app inherits

Nothing here is decoration. Each rule exists because a current screen makes a specific job harder — finding the blocking number, telling a guess from a decision, or getting from a number to the place you change it.

1 · Everything actionable is a link, and there are several routes to each place

A count, an item code, a finish code, a filename, a designer, a date, a run name — all of them go somewhere. There is no cost to offering the same destination three times, and there is a real cost to a figure that makes somebody go and find the screen it belongs to.

A number that blocks something carries its fix beside it. “312 needed to quote” is a link to the filtered table and has a Chase them button on the same row.

The cards on a project are also tabs. Runs, Finishes, Documents and History are reachable from the tab bar and from the page, because which one you reach for depends on whether you already know where you are going.

2 · A summary tile is a filter

Pressing a tile opens the list already narrowed to it. The tile you are on is outlined, and the filter is repeated as a chip you can remove — a filter you cannot see is a filter you forget you set.

Rule that goes with it, carried over from the chase screen: a filter narrows what is LISTED, never what is asked or what an edit touches. The counts on a row stay the row’s own, with “n shown” beside them only when the list was actually narrowed.

3 · Do not explain in a paragraph what a hover can say

This is a tool for professionals who use it every day. A caption under every field is read once and then becomes noise that pushes the content down the page. Where a field genuinely carries a rule worth knowing, it gets a ?A 14px circle. Hover shows one or two sentences. Never more — if it needs a paragraph it belongs in the docs, not on the screen. beside its label.

What stays on the page in words: anything that would otherwise be silently wrong. “No programme recorded — nothing can be flagged overdue” stays visible, because its absence looks identical to being on time.

4 · Colour means one thing each

Red blocks money going out. Needed to quote, a refused confirm, an export that would wipe fields.
Amber needs a person. TBC, no category, no level, a held email. Not an error.
Blue the app is suggesting. Always with its reason, always one click to accept.
Green settled. Confirmed, N/A, review complete, and a named baseline.

Slate-dashed keeps its own meaning from the gate panel — nowhere to record it, where the fix is a seed or a migration and not a question for the reader. It is deliberately not red, because putting it in the red list teaches somebody to ignore red.

5 · A guess is one click from a decision, and never wears its authority

Dashed blue, with the evidence beside it. Pressing it accepts. Where several can be accepted together there is one button for all of them, because 59 records must not mean 59 visits.

the code WD says so   

Never a pre-selected dropdown. A select already reading “Simple” fires no change event when somebody chooses Simple, so the one action recording their agreement would do nothing at all.

6 · A version is not a change

In any trail, an ordinary change is a row. A baseline — a point somebody named and can compare against — is a bar straight across, so you can see at a glance which changes fall inside it. Key dates sit in the same trail in violet, so the programme reads against the work.

7 · Layout, type and rhythm

Three bands on every page: identity bar (breadcrumb, name, status, page-level actions right-aligned) · tabs with counts · content, numbers first. Content is 1100px centred; dense tables go full width. One rule everywhere — today it is max-w-5xl on some screens and full width on others.

A list of more than six things is a table. Stacked bordered cards are for a single object you are ruling on. A list you are scanning gets aligned columns.

8 · A link goes somewhere; a button does something

Unchanged from Button.tsx — four variants, plus the suggestion. What changes is that they are used consistently: today Start a change, which opens the trail everything else attaches to, renders fainter than the link beside it.

The measure of it. Not whether it looks modern — it is a B2B tool and functionality wins every argument. The test is whether the blocking number is the first thing you see on each page, whether a guess is still obviously a guess, and whether you can get from any number to the place you change it without going via a menu.

Notes on this one
  • A version and a baseline do not look alike. Versions are numbered rows; a baseline is a green bar straight across the column with its name on it. Scrolling the list, you can see which versions fall inside Rev A and which came after — which is the only question anybody asks of it.
