## Checked against the repo

Four things said on the call do not match the code. All four were checked in
the source.

1. **"Just telling it to accept PDFs" (27:22) is not a small change, and it is
   on the excluded list.** CLAUDE.md lists "PDF bills of quantities" under
   *Explicitly excluded*, and a bill inside a PDF is refused at classify time.
   The bill rule is that **the model reads the STRUCTURE and code reads every
   cell** (Max, 2026-09-23). The drawings path, which Max named as the
   precedent, has the model reading the values, and the bill rule exists to
   forbid exactly that. There is a route that keeps the rule: `npm run
   pdf:schedule` (`tools/pdf-schedule-to-xlsx.ts`) reads a PDF *printed from
   Excel* by its own text layer, with no model. It could be offered at upload.
   It carries no pictures, and it works only on Excel-printed PDFs. **Max's
   decision (Q1).** Nothing is to be built before it.
2. **The seat height was dropped, not just shown badly.** `planSheetDescriptions`
   in `src/lib/bill-description.ts` (around line 723) writes any later Dims line
   that reads as a size as a note, *"states the same size again"*. It does
   not check whether that line states a slot the placed line left empty.
   `SH: 420MM` is such a line. CLAUDE.md's rule is "Never two attributes on one
   slot", and an SH beside W/D/H breaks nothing. This is a defect.
3. **"It is going in" (36:13) about a 710 height is wrong.** `700 DIA X 710MM`
   composes `Dia.700mm`, and the 710 is kept only inside a note. The record has
   no H. **The cause is not diagnosed.** The note reads as if the bare 710 was
   taken as the reading's qualifier. That would follow CLAUDE.md's rule that a
   line mixing prefixed and bare parts gives the bare part no slot. If so, the
   rule is working as written, but the note's wording ("not one of the five
   slots") is wrong, and the reviewer has no control to make it H.
4. **The "bill's finish reference column" is not a notes column there.** On
   TB-05C the whole cell went into Main metal finish, which ships to BWS. This
   is by design: "A finish cell is one attribute, classified whole" (CLAUDE.md,
   *Four new bills*). The design did not foresee a cell that begins with the
   item's name.

One more that the repo answers: **the pouffe has a seeded category, and it is
not the one Matthew chose.** `db/seed/0004_category_aliases.sql` maps `Pouf` →
*Ottomans Storage boxes*, written on 2026-09-30 as "this repo's judgement, for
Matthew to confirm", with the reason that the Armchairs sheet asks back
cushion, back build and swivel, which a pouf does not have. This bill spells
it `POUFFE`, so the alias did not fire, and Matthew put it in Armchairs (D1).
**Do not seed "Pouffe" either way until he has seen both readings (Q2).**
